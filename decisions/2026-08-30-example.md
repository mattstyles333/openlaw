# Law lives in git markdown, not a vector store

## Context

Canon is adopted by organisations that already have wikis, ticket
systems, and memory/recall tools for agents. Those tools are useful for
*remembering*, and they are the wrong place to put *constraints*.

If law is embedded and retrieved-when-similar, then:

- two sessions can load two different subsets of policy;
- a close-but-wrong neighbour in vector space can silently override a
  hard rule;
- there is no reviewable diff when policy changes.

Northwind Coffee (the fictional example company in this template) needs
the opposite: the same constraints on every session, in files owners
can read in git.

## Decision

Always-on law is git markdown, never a vector store. Agents load
`AGENTS.md` and `law/` every session. Retrieval is not a substitute.
Memory products are not the system of record for policy (see
`law/sor.md`).

Optional MCP, when present, is a projection of these files. It does not
search a vector index for "relevant" law. `get_law` returns the current
files, not a ranked subset.

## Consequences

- `AGENTS.md` stays short so it can be always-injected.
- CI greps for the hard-rule needles and rejects `law/` edits that skip
  the ADR path.
- Adopters who want recall still can — they attach a memory product
  *next to* Canon, not *as* Canon.
- Changing this decision later means a new ADR that supersedes this
  file, plus an explicit `law/` patch. Embeddings will not notice.
